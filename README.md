# GFF-2026

1年・2年合同の制作プロジェクトです。
このリポジトリに入るのは **PGのみ** です（PLは任意参加でチーム内のPGが教える／CGは共有ストレージ経由で納品）。

## フォルダ構成

```
GFF-2026/                     ← リポジトリ直下に Assets/ と ProjectSettings/ が並ぶ
├── Assets/
│   ├── _Project/             ← 本番。ゲームに入るものはすべてここ
│   │   ├── InGame/           ← インゲーム画面一式
│   │   │   ├── InGame.unity  ← 本番シーン（配置は2年生が担当）
│   │   │   ├── Scripts/      ← 機能ごとにサブフォルダを切る（下記）
│   │   │   └── Prefabs/      ← Scripts と同じ分け方
│   │   └── Settings/         ← URPアセット・Volumeプロファイルなど
│   ├── _Sandbox/             ← 砂場。各自の実装・動作確認用
│   │   └── <自分の名前>/
│   │       └── <自分の名前>.unity ← 自分専用の作業用シーン
│   └── InputSystem_Actions.inputactions
├── Packages/
└── ProjectSettings/
    └── NameTagSettings.asset ← 名前タグの登録と割り当て（リーダーのみ変更）
```

### 運用ルール：機能で分けて、機能に担当者を付ける

**自分の名前のフォルダを `_Project` に作らないでください。**
人ごとにフォルダを分けると「プレイヤーのコードはどこ？」に人に聞かないと答えられなくなり、誰かが抜けたときに何が本番か分からなくなります。

「他人のものを触って壊したくない」という不安は正しいので、**分け方だけ変えます。**

1. **本番のコードは `_Project` の機能フォルダに書く。** 担当は下の担当表と名前タグで示す
2. **`_Sandbox/<自分の名前>/` は自由に使ってよい。ただし本番から参照してはいけない。**
   本番のシーンやPrefabが砂場のものを使っていたら、レビューで差し戻します
3. **他人の担当フォルダを変更したいときは、PRで担当者にレビューしてもらう**

砂場で作ったものを本番に入れるときは、Prefabにして機能フォルダに**移す**。この「移す」がPRになるので、本番に入るものが自然に整理されます。

### 機能フォルダの切り方

シーン単位のフォルダ（例：`InGame/`）の中で、`Scripts/` と `Prefabs/` を機能ごとに分けます。

```
_Project/InGame/
├── Scripts/
│   ├── Player/
│   ├── Enemy/
│   ├── Stage/
│   ├── UI/
│   └── Common/      ← 共通処理。2年リーダー担当、触るときは宣言
└── Prefabs/
    ├── Player/
    ├── Enemy/
    └── ...
```

- タイトル画面やリザルト画面など、シーンが増えたら `_Project/Title/` のように同じ形で追加する
- 複数シーンで使う共通処理は `_Project/Common/` を作ってそこに置く
- 空のフォルダはGitに入らないので、新しく作ったフォルダには `.gitkeep`（空ファイル）を置く
- アセットストアなどの外部素材は `Assets/ThirdParty/` に入れる（`_Project` に混ぜない）

### フォルダ担当（NameTagの名前タグと一致させる）

| フォルダ | 担当 |
|---|---|
| `_Project/InGame/Scripts/Player` | |
| `_Project/InGame/Scripts/Enemy` | |
| `_Project/InGame/Scripts/Stage` | |
| `_Project/InGame/Scripts/UI` | |
| `_Project/InGame/Scripts/Common` | （2年リーダー） |
| `_Project/Settings` | （2年リーダー） |

### 名前タグ（NameTag）

Projectウィンドウのフォルダ・ファイルのアイコン右下に、担当者の名前を表示するエディタ拡張です。

- フォルダを選び、インスペクタ下部の **Name Tag → Assignee** から担当者を選ぶ
- フォルダに付けたタグは中のファイルにも引き継がれて表示される（グレーの斜体）。担当が違うファイルだけ個別に付ける
- 割り当てはGUIDで管理されるので、砂場から機能フォルダへ移動してもタグは外れない

> [!IMPORTANT]
> **名前の登録とタグの付け替えは、2年リーダーだけが行います。**
> 登録と割り当てはすべて `ProjectSettings/NameTagSettings.asset` 1ファイルに保存されるため、複数人が別ブランチで付け替えるとコンフリクトします。
> 担当が変わったらリーダーに頼んでください。

## シーンとPrefab

シーンファイルとPrefabは **マージできません**（中身はGUIDとfileIDの塊で、コンフリクトしたら片方を捨てるしかない）。
そこで、**本番シーンを触る人を限定し、各作業者はPrefabを作ることに専念します。**

### 基本の考え方

- **1画面につき1シーン**を用意する（例：`Title.unity`、`InGame.unity`、`Result.unity`）
- 画面を構成するUIやオブジェクトは、**すべてPrefabとして用意する**
- **本番シーンへの配置は2年生などの配置担当が行う。** 担当以外は本番シーンを編集しない

### 作業の流れ

1. `_Sandbox/<自分の名前>/` に**自分専用の作業用シーン**を作る
2. 作業用シーンの中で実装し、動作を確認する
3. できあがったものをPrefabにし、`_Project` の機能フォルダ（`Prefabs/<機能名>/`）とスクリプト（`Scripts/<機能名>/`）に移してPRを出す
4. マージ後、配置担当が本番シーンにPrefabを配置する

### 守ること

- **本番シーン（`_Project` 内の `.unity`）を試しに触らない。** 確認はすべて自分の作業用シーンで行う
- 他人の作業用シーンは開いて見てもよいが、保存しない
- Prefabは細かく分け、担当が違う部分は別のPrefabにする（見た目・当たり判定・UIなど）
- 敵の種類違いなどは、Prefabをコピーせず **Prefab Variant** で派生させる
- 本番シーンにしか置けない設定（カメラ・ライト・マネージャ類の参照など）を変えたいときは、配置担当に依頼する

| シーン | 配置担当 |
|---|---|
| `_Project/InGame/InGame.unity` | |

## ブランチ運用

```
main ─────●─────────●─────────●
           \       /  \       /
  feature/  ●──●──●    ●──●──●
```

- **`main` は常に動く状態を保つ**
- **`main` への直pushは禁止。** 作業は必ずブランチを切ってから
- 完成したらPRを出し、レビューを受けてから **2年生のマージ担当** がマージする
- `develop` ブランチは作らない
- 動かない状態でマージしない

### ブランチ名

| 種類 | 形式 | 例 |
|---|---|---|
| 機能追加 | `feature/<機能名>` | `feature/player-move` |
| 不具合修正 | `fix/<不具合名>` | `fix/jump-double-input` |

最初は機能単位（`feature/player`）で大きめに切ってよい。制作が進んでタスクが見えてきたら、`feature/player-jump` のようにタスク単位にしてPRを小さくする。

### コミット

- **1機能1コミット。** 「今日の作業」でまとめて1コミットは大きすぎる
- メッセージは日本語でよい。**動詞で始める**
  - 例：`プレイヤーのジャンプを実装` / `接地判定のバグを修正`
- 2年生は `feat:` `fix:` などのprefixを付けてもよい（任意）

### PRレビューで見ること

- [ ] `ProjectSettings/ProjectVersion.txt` に差分がない
- [ ] `ProjectSettings/NameTagSettings.asset` の差分はリーダーによるものか
- [ ] 本番シーン（`_Project` 内の `.unity`）の変更は配置担当によるものか
- [ ] 本番（`_Project`）が `_Sandbox` のものを参照していない
- [ ] 担当外のフォルダを変更していれば、その担当者がレビューしている
- [ ] `.meta` ファイルが一緒にコミットされている
- [ ] 動く状態になっている

## リポジトリに入れるもの・入れないもの

| 入れる | 入れない |
|---|---|
| `Assets/` `Packages/` `ProjectSettings/` | `Library/` `Temp/` `Logs/` `UserSettings/` `obj/` `Build/` |
| **`.meta` ファイルはすべて**（消すと参照が切れる） | 素材の元データ（`.psd` `.blend` `.max` `.aep` など） |

不要なものは `.gitignore` で除外済みです。SourceTreeの変更一覧に `Library/` などが出てきたら、コミットせずに相談してください。

プロジェクト設定（変更しないこと）：

- Project Settings → Editor → Asset Serialization = **Force Text**
- Project Settings → Version Control → Mode = **Visible Meta Files**

## 素材の受け渡し（CG・PLとの連携）

CG学生はGitを使いません。共有ストレージ経由で受け渡します。

```
共有ストレージ/
├── 01_納品/        ← CG学生がここに置いて連絡
└── 02_取込済み/    ← PGが取り込んだらここへ移動
```

- **上書き禁止。** 連番で新規作成する（`player_v03.fbx`）
- PGがUnityに取り込み、`.meta` ごとコミットする
- インポート設定（テクスチャ圧縮、Scale Factor、Rig設定）はPGが管理する
- 元データ（psd、blend）は共有ストレージに置き、リポジトリには入れない
- PLが扱う数値データはスプレッドシートで受け取り、PGが ScriptableObject や CSV として取り込む

## 困ったとき

| 症状 | 原因 | 対処 |
|---|---|---|
| pushできない | リモート未設定／認証切れ／behind | まずpullしてから再push |
| `Library/` が差分に出る | `.gitignore` が効いていない | コミットせずに相談 |
| 他人の変更が消えた | 強制pushした | **直ちに報告する。** 履歴から復旧できる |
| 本番シーンがコンフリクト | 配置担当以外が本番シーンを編集した | 配置担当の変更を採用し、自分の変更はPrefab側に移す |
| Prefabが壊れた | `.meta` を消した／解決を誤った | 前のコミットから戻す |
| マージ後に動かない | 片方の変更だけ採用した | コンフリクト箇所を再確認 |
| Unityのバージョンが上がった | 6.3 以外で開いた | `ProjectVersion.txt` を含む変更を破棄し、6.3で開き直す |
| `NameTagSettings.asset` がコンフリクト | 複数人が名前タグを付け替えた | どちらかを採用し、リーダーが付け直す |
| 名前タグが表示されない | パッケージ未導入／名前が未登録 | Package Managerで導入を確認し、NameTag Settingsに名前があるか確認 |
| 砂場のものが本番で使われている | `_Sandbox` から参照した | 機能フォルダに移してから参照し直す |

**詰まったら30分以内に聞くこと。** 黙って抱え込むと半日溶けます。
質問は「何をしようとして、何が起きたか、エラーメッセージは何か」をセットで。
